# 风序 · 风资源自动化分析平台

需求与方案阶段交付，依据上传的需求文档及两份可研参考文件设计。

- [设计方案](docs/设计方案.md)：需求拆解、模板映射、统计口径、交付阶段与风险。
- [架构文档](docs/架构文档.md)：组件、数据模型、API、版本谱系、扩展与验证计划。
- `docs/设计方案.docx`、`docs/架构文档.docx`：便于下载审阅的Word版本。
- [图表目录](docs/图表目录.csv)：从辅助模板提取的40张表和24个图位。
- `gui/`：白色圆角风格交互原型。

## 运行GUI

无需安装依赖，使用Python 3：

```sh
cd /workspace/Wind-Resource
python -m http.server 8000 --bind 0.0.0.0 --directory gui
```

浏览器打开该服务器的 `/`。也可直接打开 `gui/index.html`。后续任务使用现有检出目录，无需创建Git worktree。

页面覆盖工作台、数据导入、分析配置、图表、报告、规范管理。CSV/TXT可本地解析、映射并预检；下载示例CSV可用于体验。结束日期不含在统计区间中。回溯10/20/30年窗口随配置更新。上传后的基础统计替换图表中心的合成示例，长序列仍明确标记为示例。支持下载配置JSON、当前结果CSV、含人工标黄的报告HTML。

**边界**：浏览器内存处理，刷新丢失；不上传云端。XLS/XLSX提示未实现，不冒充解析成功。专业规范算法、相关回归、MCP、Weibull、正式DOCX、账号权限、后台队列和云端原件/初版存储均为架构设计，尚未实现。概览风况曲线始终为合成布局示例。

## 当前GUI：V0.2

新版分为五个板块：项目信息、数据中心、分析配置、图表可视化中心、报告预览。图表目录提供13类参数图形，并绑定横向比较后母版的2.1—2.10章节。可搜索图表、切换示例对象与数据来源、查看数据表、下载SVG/CSV，并在图表和报告之间跳转。

真实CSV/TXT导入保留基础预检，支持月均、日内、自然年风速、频率和风向玫瑰。密度/切变/湍流/Weibull/功率密度/风能玫瑰/同期相关/长期中尺度的真实计算未接入，仅提供标识清楚的合成图形方案。图表阶段不匹配或缺输入时显示缺项，不自动生成或猜测结果。真实文件尚未建立塔号/高度映射，不将文件统计视为已完成的轮毂代表年成果。

项目信息、上传数据和分析配置暂存当前页面会话，刷新丢失；未实现云端保存。报告下载仍是带黄色待补项的HTML草稿，不是正式DOCX。

单文件GUI：运行`python tools/export_standalone.py`生成`dist/风序-GUI.html`，可下载后用浏览器打开；该文件不提交Git，来源始终是gui/。当前版本号见gui/version.json。网页发布是否生效仍以GitHub Pages部署为准。

## 当前GUI：V0.3组合图

图表组合在`gui/viz-v03.js`实现，沿用已有五板块与数据导入。图表顺序为长期中尺度、四阶段概览、密度、相关性、切变、湍流、月度、日内、频率；Weibull与两种玫瑰作为补充图谱保留。

组合视图支持四曲线独立开关、1/12/16相关性分组、10/20/30年基准和演示阈值、左右双轴、多高度表、横向年份表、密度平均值红柱。散点不附表，长期风况的比较表放在柱图旁。

偏差系数使用“测风年同期中尺度”与“长期中尺度均值”比较，另列测风塔实测年均值，避免跨来源混算。原需求“30年、20年、20年”按后文解释为30/20/10年。演示平风年阈值可调，不能视为已批准标准。

所有新增专业组合视图为明确标识的合成布局；真实CSV导入仍仅支持此前的基础单文件统计，无法由仅均速文件得到密度、切变、湍流或四阶段对齐等专业结果。真实来源模式将说明缺项，不显示合成值冒充实际成果。

V0.3.1统一展示顺序：先图形，再表格，最后计算规则与说明。各高度表保留对象标题；曲线开关和扇区等交互仍位于图前。相关性散点不附表，长期风况比较表在图后。

## 当前GUI：V0.4功能看板

五个模块职责：项目管理负责进行中/已完成项目的本地查询归档；数据管理接收原始、QC、订正外推轮毂高度、中尺度四类资料；分析配置统一填写项目容量、装机台数、轮毂高度等；图表采用横向A概览/B密度/C相关/D参数看板，目录和结果从左到右展开；报告区明确可研模板与可用HTML导出格式。

项目元数据和归档报告文字快照保存在本浏览器localStorage（最多加载500条），支持刷新后查询、JSON导出备份。归档项目只读，可复制为新项目。切换项目会清空当前文件内存与基础统计，防止跨项目误用；原始文件、上传资料和云端资产不包含在归档中。浏览器存储失败时明确退回当前会话，提示导出备份。不同浏览器/设备不能共享本地档案，清理站点数据会移除档案；尚未实现JSON恢复导入、云端同步和正式审签。

A的合成预览可选择中尺度（1995—2024）或测风塔（2020—2024）源、示例高度和日期范围，均值及风向随所选样本变化。C的2024年合成配对样本按时间与扇区共同筛选，无样本时不拟合。真实专业数据链及高度/时间筛选仍未接入，页面明确披露。B的“有参证站资料”是图形演示开关，不表示已上传气象站数据。

V0.4界面编排位于gui/workspace-v04.js。原架构方案未改写。

## 当前开发模块：V0.5真实数据输入与概览

使用数据管理顶部“真实多文件识别与测风概览”导入四阶段CSV/TXT/XLSX。候选识别后可修正阶段、工作表、时区、时间/风速/方向/标记字段及高度。通过确认后，A看板使用实际文件计算年度/方向统计和四线对比，并以最终完整年结束时刻自动定位10/20/30年中尺度窗口。

仅A板块接入真实多文件数据链，未重复进行QC、订正或外推；B/C/D专业计算仍未实现。下方旧单文件预检是兼容工具，不参与四阶段概览。新模块支持XLSX（包括工作表选择），此前版本关于Excel未支持的说明仅适用于旧工具。

详细规则、限制与实际样本待办见[数据输入与识别](docs/数据输入与识别.md)。此轮未收到用户测风附件，当前验证使用独立生成测试集。

检查命令：`node tests/data-core.test.js`；启动GUI服务后`python tests/data-browser.py`验收实际导入、数值与绘图，`python tests/smoke.py`检查既有功能。单文件网页仍通过`python tools/export_standalone.py`生成。客户数据仅在浏览器内存，不上传Git或云端。

## 当前开发模块：V0.6关键字通道识别

已嵌入用户提供的关键字/排除词库，按“参数类型 × 高度 × 统计量”识别每列。数据管理可查看规则、导出JSON，并在每个文件的逐列识别表修正要素、统计量和高度。只有已确认的均值风速进入概览，标准差/极值分别保留；温度、气压、湿度、电压按通道与高度提取，排除项不自动使用。

详细优先级、匹配例子、单位、数据结构和限制见[通道关键字识别](docs/通道关键字识别.md)。规则模块为`gui/channel-library.js`；可直接复用的接口是`ChannelLibrary.identify()`和`WindData.detect()`。仅新增识别与数值保留，没有宣称空气密度/湍流引擎已实现。

新增检查：`node tests/channel-library.test.js`、`python tests/channel-browser.py`；既有核心、四文件导入与看板测试继续运行。截图使用生成数据，不包含客户原件。

## 当前上传流程：V0.7

数据管理使用四行清单。批量文件按“原始数据、质控后/删除标记后数据、结果数据、中尺度数据”名称归类；单独入口已指定类型，可用任意文件名。各行独立删除、替换和重新上传。程序自动匹配可确定的表头，未知列、缺高度、同高度主通道冲突或多工作表将弹出人工映射窗口；可指定或明确忽略，确认后继续处理。

标准命名包括WS-100m、WD-100m、WPD-100m及STD/MAX/MIN后缀，保留原始表头和识别依据。支持标准列名JSON与标准表头CSV下载（CSV保留原始单位）。识别、映射、命名完全由本地程序执行，不调用AI或远程识别服务。

详见[四类上传与标准通道](docs/四类上传与标准通道.md)。新增`node tests/standard-channels.test.js`和`python tests/upload-browser.py`；其余测试已迁移到新入口。旧卡片式导入和兼容预检不再作为用户入口；此前V0.5/V0.6操作步骤为历史版本。
