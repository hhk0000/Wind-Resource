# 风资源自动化分析平台 · 设计方案 V0.1

状态：需求与方案评审稿。交付包含平台框架、架构和交互原型，不代表专业计算引擎或云端持久化已实现。

## 1. 设计依据与边界

需求依据为《需求文档.txt》；工程内容以《NY10957NK-A01.docx》第2章为主，章节组织以《04-标准可研模板.docx》为辅助归一化。后者自述参考的《可研上册》本次未单独提供，不声称已完成对其独立比对。附件中的公式、规范号、阈值及示例结论均是待核验参考材料，不直接视为生产执行规则。NY10957 中的项目名称、坐标、塔号和统计值不能继承为新项目事实。

本期建设第2章“风能资源”的分析及报告工作流；完整可研中的地质、电气、土建、发电量、概算、财务暂不自动生成。支持多项目、多场区、多塔、多高度；初期一个项目完整闭环优先。借鉴 Easy Data / Easy Report 的数据与报告分层思路，不声称已调研其内部实现。

## 3. 用户与业务闭环

分析人员创建项目→登记塔与通道→上传并映射→确认时间/单位/标记→冻结数据版本→配置统计与长序列窗口→预检→提交任务→审阅图表→补写标黄段落→生成初版→审核→下载。审核人员批准规范和结论；管理员配置模板、存储及权限。作者不能以一次点击替代专业审核。

P0允许直接使用外部QC及最终代表年文件；平台内自动QC、插补、MCP订正与外推是独立可选步骤，每步创建新版本，原始资料始终只读。

## 5. 统计与图形口径

- 时间统一存UTC，展示使用项目时区；输入时区未确认不冻结数据。区间采用[start,end)，采样步长明确，应测数按时间网格生成，包含闰日。重复时间、偏移时间分别列出；同一通道同一时刻最多计一个有效样本。
- 实测完整率=有观测的唯一时间格/应测格；有效完整率=通过QC的格/应测格；插补覆盖率单独列示。整月、整年及总计按样本加权，禁止平均月完整率替代总体完整率。90%只作待核验模板示意，不硬编码为合规结论。
- QC保存缺测、超量程、恒值、塔影、结冰等独立标记，规则阈值可版本化。与用户删除标记并存；人工覆盖须有理由和审计。
- 功率密度计算有效样本的 mean(0.5×ρ×v³)，不以平均风速立方代替；缺密度输入时报告缺项，显式指定固定密度时附假设。
- 风速频率默认1 m/s箱宽可改，区间左闭右开，末箱含最大值；风能频率用ρv³权重归一化。静风阈值、归一化分母及缺测排除规则随结果保存。
- 风向采用气象来向，北0°顺时针；默认16扇区，边界跨北归并。风向/风能玫瑰分别使用有效风向样本与能量权重；静风单独列出，不伪配方位。
- Weibull拟合采用MLE，零风速单独报告；保存k、尺度c、样本数、拟合优度与经验直方图，拟合失败不可返回默认参数。
- 日变化按项目当地小时分组；月变化按实际月份；不同高度采用同期有效样本，异步样本需披露。
- 中尺度与测风先聚合到同期小时，风向用圆统计，核验时区与最小小时覆盖率；16扇区默认以参考序列来向分组，输出n、a、b、Pearson r、R²及残差。低样本或零方差扇区不拟合；阈值由项目审批。不得把r与R²混用。
- 窗口默认以所选测风年结束日期为截止锚点，向前回溯10/20/30个日历年，[anchor-N年,anchor)。例如测风年[2024-01-01,2025-01-01)，10年窗口为[2015-01-01,2025-01-01)。允许改为最近完整自然年模式，保存选择。2月29日回溯无同日时取2月28日，列出不完整首尾年；缺年不自动缩短标题而不告知。
- 密度P/(R×T)要求Pa、K及高度来源；切变要求正风速与同期高度配对；湍流要求同时间窗标准差，不能从仅均值序列反推；极值必须记录平均时距、极值样本独立性、参考高度、重现期及分布假设。

## 6. 报告设计

标准模板采用具名占位符与章节块，不靠字符串替换编号。图优先SVG并生成PNG兼容Word；表保留可编辑单元格。封面、页眉页脚、目录、题注、单位、编号与交叉引用按标准模板样式实现；最终分页与Word域更新需在目标Office版本验收，不承诺跨软件像素一致。

未完成字段用黄色高亮，附责任人、原因与来源。初版可在未补齐时导出但标识“草稿/未审”，正式版必须通过数据、规范、人工项三个闸门。原始文件与首次报告对象不可覆盖，后续修订生成新版本；下载支持DOCX、图表包、结果CSV，PDF作为后续排版验收项。

## 7. 页面与交互

左侧固定项目导航，顶部显示项目、塔、版本及保存状态；主区白底圆角卡片、蓝色主操作、黄色待确认提示。工作台展示任务与资料状态；数据中心四类上传槽和字段预检；分析配置提供测风时段、10/20/30年窗口、轮毂高度、扇区；图表中心切换月变化/频率/玫瑰/长序列；报告工作室用章节树+纸张预览+人工项清单；规范中心显示待审核状态。

本次GUI是无第三方运行依赖的交互原型：CSV/TXT可本地解析、字段映射并计算基础风速和完整率；XLSX仅识别选中文件并提示未来解析服务，不能假装解析成功。示例模式图表使用独立标识的合成数据。可导出原型分析JSON、结果CSV、报告HTML；HTML不冒充生产DOCX。原型数据只在浏览器内存，不上传云端；正式对象存储、账号、后台任务与DOCX生成在架构文档中设计。

## 8. 分期与交付门槛

阶段A（本次）：需求矩阵、标准章节、图表目录、架构、可交互GUI；评审重点为数据口径与人工边界。
阶段B：真实导入、对象存储、元数据库、版本追溯、基础统计和图表、DOCX草稿闭环；用用户样本验证四类数据、多塔和多高度。
阶段C：规范审核与算法插件，MCP、插补、外推、极值及审签；使用独立工程基准复核。
阶段D：多租户、模板可视编辑、布局扩展与性能优化。工期需结合样本、规范及团队人数评估，不承诺未经验证的时间。

## 9. 风险与待确认

|风险|影响|处理/验收|
|---|---|---|
|规范未提供、版本冲突|错误等级与安全结论|算法默认待审核，工程师批准方法及适用域|
|只有删行后数据|删除原因不可恢复|保留原件，差集比对并披露无法恢复项|
|时区/步长/闰日/重复行|完整率和相关性失真|字段确认与时间网格预检，人工核对样本|
|最终数据重复订正|系统偏差|阶段锁与谱系检查，默认跳过处理|
|长序列年限不足|“30年”结论失实|展示请求及实际覆盖、缺年清单，阻断完整30年标签|
|方向扇区样本不足|拟合不稳定|逐扇区n、阈值、失败原因与人工确认|
|模板公式不一致|计算方法误用|候选方法注册，核验标准后启用|
|图表与正文版本不一致|报告无法追溯|冻结AnalysisRun，一份结果供表/图/文共同引用|
|异步重试重复初版|资产覆盖|幂等键、事务与不可变对象版本|
|大文件与恶意表格|资源耗尽/文件风险|大小/解压比/行数限制，隔离解析，禁宏、公式不执行|
|云端资料敏感|泄露/误删|项目级鉴权、短期签名URL、加密、备份恢复演练|
|Word排版差异|交付版式失真|以目标Office/纸张规格进行文档回归验收|

待下一轮确认：真实四类样本及删除标记编码、采样步长、项目时区、通道/高度命名；规范及授权；测风年窗口锚点；部署区域、保留期限与协作权限；报告签审流程；是否需要旧版XLS与PDF。以上不阻塞当前方案和原型，但会约束生产实现。
